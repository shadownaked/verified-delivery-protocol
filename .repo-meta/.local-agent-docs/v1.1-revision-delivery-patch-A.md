## 1. 变更摘要（What & Why）

### 修正"检查器自身空转成假绿"（S2-1，最重要）
复核复现了最危险的一种形态：枚举失效时四项检查对空集判 PASS，汇总与健康态**完全相同**。
v1.1.1 建立三层防线：

1. **能力探测**：前置检查 `find . -name "*.md" -not -path "./dist/*"`，失败直接 `BLOCKED`（exit 2）。
   这条专门防 Windows `find.exe` 抢占 PATH——它对本仓库就是静默失效。
2. **空集拦截**：主体 md 枚举结果为空 → `BLOCKED`（exit 2），永不对空集判绿。
3. **规模下限**：`SCOPE_MIN_FILES=30`，主体 md 数量低于下限 → `FAIL`；[10] 另有独立下限断言。

同时把 [5] 的断言从"纯比例"恢复为"比例 + 数量下限"，比 v1.1 更严，不属于削弱断言（F12）。

### 产物新鲜度覆盖全部源（S2-2 + S3-5）
新增 `scripts/complete-sources.txt` 作为合并清单的**单一事实源**：
`build-complete.sh` 与 `scripts/test.sh` [6] 读同一份文件 → "被比对的集合"与"实际嵌入的集合"
不可能漂移。清单同时纳入 `docs/AUTHZ.yaml`、`docs/bench/benchmarks.yml`、`evidence/` 5 份模板
（嵌入 30 → 37），解决了复核指出的"22 个源改动不被发现"和"快照不含机器可读授权表"。

### 执行位与跨平台诚实（S2-3）
`scripts/{bench,test,build-complete}.sh` 索引模式 `100644 → 100755`（`git update-index --chmod=+x`），
[9] 逐个校验；无 git 时回退 `-x`；两者都不可判定时输出 `N/A`（明示，不计入 PASS）。

### 自检与真实基准解耦（S2-4）
`bench.sh` 新增 `VDP_BENCH_CONFIG` 环境变量；[9] 用临时合成配置只验证契约三路径
（未配置→2 / 成功→0 / 失败→1），**绝不读取** `docs/bench/benchmarks.yml` 的实际基准。
R10 变异测试：在副本中把真实基准写成会落盘标记的命令，自检全程该标记未出现。

### bench 证据链语义（S3-4 + S3-9）
- 退出码 3 落地：时间戳获取、证据目录创建、meta/summary 写入失败 → `BENCH: ERROR` + exit 3。
  语义：**证据链断裂**，本次测量不可采信；与"基准失败（1）"分开。
- 证据目录重名不再覆写：同秒运行自动 `-1/-2`（R8 实测两个目录并存）。

### 其余修正
- **S3-1**：`AUTHZ.yaml` 的 allow/ask 从空数组改为与 `AUTHZ.md` 一一对应的默认条目，两处均标注"模板默认值，接入时替换"。
- **S3-2**：`.gitignore` 版本戳 v1.0 → v1.1。
- **S3-6**：主体 md 枚举改为 `git ls-files --cached --others --exclude-standard`（天然排除 `node_modules/`、`vendor/`），无 git 时 find 加第三方排除。
- **S3-7**：`CHANGELOG.md` 不再引用 `.repo-meta/...` 路径（改为"审计全文与过程记录属仓库管理元信息，不进入模板"）。
- **S3-8**：`AGENTS.md` §4 顶部标注"本节为完整集，ENGINEERING.md §5 为最小集"。

## 6. 兼容性说明（Compatibility / Migration）

1. **需要新文件**：下游沿用本 `test.sh` 必须同时引入 `scripts/complete-sources.txt`；[6] 靠它判定
   覆盖范围。裁剪清单是显式 diff（可审计），**不允许留空**（留空会被 [6] 判缺失）。
2. **执行位要求**：三个脚本需在 git 索引中为 `100755`。Windows 下 `core.filemode=false`，
   只能靠 `git update-index --chmod=+x` 维持；不愿启用该约束的项目应删除 [9] 对应子项并记录理由。
3. **自检不再跑真实基准**：原本依赖"开工自检顺便跑一次 bench"的项目，改为在 CI 中显式调用
   `sh scripts/bench.sh`。
4. **dist 覆盖变化**：`docs/bench/benchmarks.yml` 与 `evidence/*` 现已进入合并版，因此下游修改这些
   文件后，若仍保留 [6] 检查，会报"产物过期"——这是正确行为，重建产物即可。
5. **断言更严，方向是收紧而非放宽**：空集/半空集从"判绿"改为"FAIL 或 BLOCKED"；
   [5] 恢复数量下限。[6] 的计数改为动态派生（不再硬编码 30/37），但覆盖范围扩大。
